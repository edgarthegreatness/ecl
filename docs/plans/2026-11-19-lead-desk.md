# Lead Desk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved Lead Desk mockup into a working Netlify app. It collects leads from several Facebook Pages, drafts replies for approval, sends them on the allowed channel, logs to Google Sheets, emails alerts and raises follow-up reminders.

**Architecture:**
- **Front end:** a static app in `public/`.
- **Back end:** Netlify Functions v2 in `netlify/functions/`, with `export default async (req, context) => Response` and `export const config = { path | schedule }`.
- **Storage:** one Netlify Blobs store, `leaddesk`.
- **Business logic** is pure ES modules in `lib/core/`, with no Node APIs, so it can be unit-tested locally with macOS `jsc`.
- **Service code** that talks to Facebook, Google, Gmail and Blobs lives in `lib/svc/`, and is syntax-checked only.

**Tech Stack:**
- Netlify (Functions v2, Scheduled Functions, Blobs), Node 20 runtime, `@netlify/blobs`, `nodemailer`.
- Facebook Graph API (default version `v23.0`, overridable by env).
- Google Sheets API v4, via a service-account JWT signed with `node:crypto`.
- Vanilla HTML, CSS and JS front end.

**Spec:** `fb_leads_app/DESIGN.md`. Approved UI: `fb_leads_app/mockup.html`.

## Global Constraints

- **Repo root:** `fb_leads_app/lead-desk/` (git repo). The owner uploads it to a **private** GitHub repo, which Netlify deploys.
- **Never auto-send.** Every outbound message goes through `POST /api/leads/:id/send`, triggered by the owner's tap.
- **No secrets in the repo.** All of these come from environment variables:
  - `FB_APP_ID`, `FB_APP_SECRET`, `FB_VERIFY_TOKEN`, `FB_GRAPH_VERSION` (default `v23.0`)
  - `SESSION_SECRET`, `SITE_URL`
  - `GOOGLE_SA_EMAIL`, `GOOGLE_SA_KEY` (PEM, with `\n` escapes allowed), `SHEET_ID`
  - `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `ALERT_EMAIL`
- **Only Pages the owner ticks** are stored or subscribed. Owner lock: the first Facebook user to sign in is stored as owner in Blobs (`owner`), and anyone else gets 403.
- **Facebook Login scopes:** `pages_show_list,pages_read_engagement,pages_manage_metadata,pages_read_user_content,pages_manage_posts,pages_messaging,leads_retrieval,pages_manage_ads,business_management`.
- **Page webhook subscription fields:** `leadgen,messages,message_echoes,feed`.
- **Look and fonts** follow `mockup.html`: dark and gold, **Bodoni Moda** headings, **DM Sans** body.
- **Default templates.** Use the generic text from `mockup.html` (form / message / comment). The follow-up template is `"Hi {first}, just checking in on my last message. Are you still interested? Happy to answer any questions."`, and the ask-for-phone suffix is `" What's the best number to reach you?"`.
- **Reminder defaults:**
  - `unrepliedAfterH: 1`
  - `quietAfterH: 48`
  - `maxFollowUps: 2`
  - `windowWarnH: { message: 3, comment: 24 }`
- **Lead statuses:** `waiting | followup | sent | skipped | failed | cold`.
- **Tests:**
  - `sh tests/run.sh` runs every `tests/*.test.js` with `jsc -m`, and prints `PASS <file>` or a stack plus a non-zero exit.
  - `sh tests/syntax.sh` syntax-checks every `.js` under `lib/`, `netlify/` and `public/`.

## Review Focus

1. **Meta retries a webhook** (duplicate delivery). There must be no second lead, Sheet row or alert. Lead ids are deterministic, and `mergeInbound` ignores an already-seen message `mid`. Pinned in Task 3.
2. **Messages sent by the Page itself.** This includes echoes of Lead Desk's own sends and comments the Page makes on its own posts. These must never become leads. An echo carrying our app id must not mark the lead "replied outside". Pinned in Task 3.
3. **A form lead with no email and no phone.** Send is refused with the reason `"No email: call or text"` (or `"No contact details"` when there's no phone either). Pinned in Task 2.
4. **A missing, one-word or odd lead name.** `{first}` falls back to `"there"`. The suffix is added only when there's no phone. Pinned in Task 3.
5. **The Messenger window closes while a lead is in the queue.** The server refuses to send, not just the UI. Pinned in Task 2 (`canSend`) and used by Task 9.

### Task 3: Leads (`lib/core/leads.js`)

**Files:** Create `lib/core/leads.js`. Test: `tests/leads.test.js`.

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `DEFAULT_TEMPLATES = { form, message, comment, followup }` (text from Global Constraints) and `ASK_PHONE`.
  - `parseWebhook(body, ourAppId) -> Event[]`. Each event is `{ kind: 'form'|'message'|'comment'|'echo', pageId, ref, fromId?, fromName?, text?, at, postId?, mid? }`.
    - `leadgen` change → `form` (ref = `leadgen_id`).
    - `messaging[]` with `message.is_echo`:
      - from our app (`message.app_id == ourAppId`) → dropped.
      - otherwise → `echo` (ref = recipient PSID).
    - Other messaging → `message` (ref = sender PSID, `mid`, text).
    - `feed` change with `item:'comment'`, `verb:'add'`, `parent_id === post_id` and `from.id !== pageId` → `comment` (ref = `${post_id}:${from.id}`).
    - Everything else is dropped.
  - `leadId(event) -> string`: `${kind}:${pageId}:${ref}`. For echo, use the kind `message`.
  - `formFieldsToContact(field_data) -> { name, email?, phone?, said }`. Name comes from `full_name`, else `first_name` + `last_name`. Email comes from `email`, phone from `phone_number`. `said` is `"Label: value · …"` for the remaining fields, with the field names title-cased.
  - `newLead(event, contact, template, now) -> Lead`. `status: 'waiting'`, `draft = renderDraft(template, lead)`, `followUps: 0`, `replyCount: 0`, `seenMids: [mid]`, `reminded: {}`.
  - `renderDraft(template, lead) -> string`. Replaces `{first}` with the first word of the name, or `"there"` when it's empty. Appends `ASK_PHONE` when there's no phone.
  - `mergeInbound(lead, event, now) -> { lead, changed: boolean, reopened: boolean }`.
    - A `mid` already in `seenMids` → `changed:false`.
    - Otherwise, append the text to `said` on a new line and set `lastInboundAt`.
    - If the status is `sent|followup|skipped|cold`, set the status to `waiting`, reset `reminded`, and set `reopened:true`.
  - `markRepliedOutside(lead, now) -> Lead`. Sets `status:'sent'` and `sentAt`, and leaves `draft` alone.

### Task 4: Follow-ups (`lib/core/followups.js`)

**Files:** Create `lib/core/followups.js`. Test: `tests/followups.test.js`.

**Interfaces:**
- Consumes: `windowEndsAt` and `canSend` from Task 2, and `renderDraft` from Task 3.
- Produces:
  - `DEFAULT_REMINDERS` (from Global Constraints).
  - `evaluate(lead, now, settings, followupTemplate) -> { lead, notify: null | { type: 'unreplied'|'window'|'quiet'|'call'|'cold', text } }`. Rules apply in this order:
    1. `waiting|followup` and an open window, with `hoursLeft ≤ windowWarnH[source]` and `!reminded.window` → `window`. Set `reminded.window = now`.
    2. `waiting`, `now - receivedAt ≥ unrepliedAfterH`, and `!reminded.unreplied` → `unreplied`.
    3. `sent`, with no inbound since `sentAt`, and `now - (lastFollowUpAt || sentAt) ≥ quietAfterH`:
       - if `followUps ≥ maxFollowUps` → `status:'cold'`, notify `cold`.
       - else if `canSend(lead, now).ok` (this is false for comments, which have already used their one private reply) → `status:'followup'`, `followUps+1`, `lastFollowUpAt=now`, draft from `followupTemplate`, notify `quiet`.
       - else if the lead has a phone → `followUps+1`, `lastFollowUpAt=now`, notify `call`.
       - else → no notify.
    4. Otherwise `notify:null`, with the lead unchanged.

### Task 8: Webhook (`netlify/functions/webhook.js`)

**Files:** Create `netlify/functions/webhook.js` with `config.path = '/webhook'`.

**Interfaces:**
- Consumes: Tasks 3, 5 and 6.
- **GET:** echoes `hub.challenge` when `hub.verify_token === FB_VERIFY_TOKEN`. Otherwise 403.
- **POST:**
  1. Reads the raw text and checks `verifyMetaSignature`. A failure returns 401.
  2. Returns `200` immediately and does the work inside `context.waitUntil(processEvents(events))`.
- **Per event**, skipping any page that isn't in `pages/`:
  - **form:** `getLead` → `formFieldsToContact` → `newLead` with that page's template. If `leads/<id>` already exists, stop. Otherwise save it, `appendRow` and store `sheetRow`, then `alert("New lead: <name> (<page>)", …)`.
  - **message:** if the lead exists, run `mergeInbound`. When it changed, save, `updateRow`, and alert only if it reopened. If it's new, `getName`, then `newLead`, save, append and alert.
  - **comment:** same as message, using `fromName` (no Graph call).
  - **echo:** for an existing lead with status `waiting|followup`, run `markRepliedOutside`, save and `updateRow`.
  - Each event is wrapped in try/catch, so one bad event doesn't drop the rest (log it).

### Task 9: App API (`netlify/functions/api.js`)

**Files:** Create `netlify/functions/api.js` with `config.path = '/api/*'`. Every route calls `requireOwner` first.

**Routes (Produces, all JSON):**
- `GET /api/me` → `{ pages:[{id,name,color}], dataAccessExpiresAt, reminders }`
- `GET /api/pages/available` → `listPages(user.token)` as `{id,name,connected}`
- `POST /api/pages {ids}`:
  - For each id: save `pages/<id>` with a color from the palette `['#d8b77a','#7aa7d8','#c08ad8','#7ad8b0','#d87a8a']` (in order), then `subscribePage`.
  - Delete and unsubscribe any connected Pages that weren't ticked.
  - Seed `templates/<id>` with `DEFAULT_TEMPLATES` if they're missing.
- `GET /api/leads` → all leads, sorted with `waiting|followup` first and then by `receivedAt` descending. Each lead includes `canSend` and `clock` from Task 2.
- `PATCH /api/leads/:id {draft}`
- `POST /api/leads/:id/send {text}`:
  1. Re-checks `canSend(lead, now)` on the server, and returns 409 with the `reason` if it fails.
  2. Sends by channel:
     - form → `sendMail` to `lead.email`, subject `"Thanks for reaching out to <page name>"`, `replyTo GMAIL_USER`
     - message → `sendMessenger`
     - comment → `sendPrivateReply(commentId from fbRefs)`
  3. **On success:** `status:'sent'`, `sentAt`, `replyCount+1`, `reminded:{}`, then `updateRow`.
  4. **On error:** `status:'failed'`, `error`, then return 502 with the message.
- `POST /api/leads/:id/skip`
- `GET|PUT /api/templates/:pageId` (keys `form, message, comment, followup`)
- `GET|PUT /api/settings` (`groups:[{name,url}]`, `groupPostText`, `reminders`)
- `GET /api/posts?page=<id>`
- `POST /api/posts {pageIds, message, link?, imageBase64?, scheduleAt?}`. Rejects with 400 if `scheduleAt` is less than 10 min or more than 30 days ahead. Returns `{results:[{pageId, ok, id?|error?}]}`.
